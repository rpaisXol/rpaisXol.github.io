# 4. 관계

관계란 엔터티와 엔터티 사이의 논리적인 연관성을 의미, 엔터티는 관계를 맺음으로써 의미 있는 정보로 확장된다. 

## 1. 관계의 종류
### 1. 존재적 관계

- 엔터티 간의 소속이나 포함 관계를 나타낸다. 
- 예) A 학생의 학과가 컴퓨터공학과라면 이 학생 엔터티는 컴퓨터공학과 엔터틸에 소속되어 있는 관계이다.
### 2. 행위적 관계

- 엔터티 간의 발생하는 행위나 사건을 표현하는 관계
- 예) 주분하다, 수강하다와 같은 경우


## 2. 표기법

### 1. 관계명(Membership)

- 두 엔터티 사이에서 일어나는 행위나 상태를 '수강한다', ' 소속된다'와 같은 동사로 직접적으로 서술 관계를 쉽게 파악

### 2. 관계차수(Cadinality)

- 두 엔터티 간 관계에서 참여하는 인스턴스 개수
- 1:1, 1:N, N:M 관계가 있고, 관계선 끝에 하나(|) 또는 여러 개(<)를 의미하는 기호를 붙힘

![[03. 관계, 식별자-1791154693748.webp|700]]

### 3. 관계선택사양(Optionality)

- 한 엔터티가 데이터가 상대방 엔터티의 데이터와 반드시 관계를 맺어야 하는지(필수적)
- 아니면 관계를 맺지 않아도 되는지(선택적)를 나타내는 규칙

# 5. 식별자

- 데이터베이스에서 식별자(Identifier)는 많은 데이터 중에 특정한 데이터(행, 레코드)를 유일하게 구분할 수 있는 기준점
- 식별자가 필요한 이유는 데이터베이스에 동일하거나 비슷한 값이 여러 개 있을 수 있음
- 중복 없이 특정 데이터를 찾아내기 위해 식별자가 필요

![[03. 관계, 식별자-1791174764965.webp]]

## 1. 주식별자와 보조식별자
- 하나의 엔터티에는 데이터를 하나로 고유하게 식별할 수 있는 여러 속성(후보 식별자)이 존재
- 모델의 일관성과 명확성을 위해, 이 후보들 중에서 엔터티를 대표할 단 하나의 식별자를 지정
### 1. 주식별자(Primary Identifier)
- 여러 후보 식별자 중에서, 엔터티를 대표하도록 선정된 하나의 핵심 식별자를 지칭
- 모델의 일관성과 명확성 위해, 이 후보들 중에서 엔터티를 대표할 단 하나의 식별자 지정

### 2. 보조식별자(Alternate Identifier)
- 데이터를 하나로 특정할 수 있는 나머지 후보 식별자
- 실제 데이터베이스에서는 대체키(Alternate Key)로 구현

| 구분  | 주식별자                  | 보조식별자                |
| --- | --------------------- | -------------------- |
| 대표성 | 엔터티를 대표하는 핵심 식별자      | 대표로 선택되지 않은 나머지 식별자  |
| 개수  | 엔터티 당 단 하나만 존재        | 여러 개 존재할 수 있음        |
| 역할  | 다른 엔터티와의 관계 연결(FK) 기준 | 데이터를 유일하게 찾는 또 다른 방법 |
| 구현  | 기본키                   | 대체키                  |

## 2. 식별자의 특징

- 좋은 식별자는 데이터를 명확히 구분, 안정적 관리
- 모든 후보 식별자는 유일성과 존재성 만족
- 이 중 주식별자를 선택할 때는 최소성과 불변성을 중요하게 여김

| 유일성 | 모든 인스턴스를 유일하게 식별                    |
| --- | ----------------------------------- |
| 최소성 | 유일성을 만족하는 최소한의 속성으로 구성              |
| 불변성 | 식별자 값은 한번 정해지면 변하지 않음               |
| 존재성 | 주식별자는 NULL 값을 가질 수 없음, 반드시 값이 존재해야함 |

## 3. 식별자의 분류

### 1. 대표성 여부
- 주식별자: 엔터티를 대표하도록 선정된 단 하나의 식별자
예) '회원' 엔터티 -> 데이터 식별 후보인 '회원번호'와 '이메일'이 존재할 때 회원번호가 주식별자로 적합함
- 보조식별자: 주식별자로 선정되지 않은 나머지 후보 식별자
예) 회원번호가 주식별자로 선정 시, 이메일은 보조식별자로 선정

### 2. 스스로 생성되었는지 여부

식별자가 엔터티 내부에서 직접 생성되었는지, 아니면 다른 엔터티로부터 받아온 것인지에 따라 분류

- 내부식별자: 엔터티 내부에서 스스로 생성된 식별자
예) 주문 엔터티의 주문번호는 새로운 주문이 발생할 때마다 해당 엔터티 내에서 직접 생성

- 외부식별자: 다른 엔터티 관계를 통에 외부에서 받아온 식별자
예) 주문상세(엔터티) -> 어떤 주문에 속한 상품인지 명시하기 위해 주문 엔터티로부터 주문번호를 받아옴, 주문상세의 주문번호는 외부 식별자
