# 01. 엔터티

- 데이터베이스 내에서 **고유하게 식별 가능한 객체(Object) 또는 개념**
- 우리가 관리하고자 하는 정보의 주제
- 엔터티는 자신을 구체적으로 설명하는 속성으로 구성
- 예) 학생 → '이름', '학번'과 같은 정보를 사용
- 예) 학생은 엔터티 / 이름과 학번은 속성
## 1. 엔터티 특징
엔터티가 DB의 핵심 구성요소이며 업무적으로 의미 있고 효율적인 좋은 엔터티가 되기 위해선 다음 다섯 가지 특징을 만족해야함

### 1. 업무 관리, 사용되야하는 정보 집합
- 엔터티는 반드시 해당 업무에서 필요로 하고 관리하고자 하는 정보
- 예) 학생이란 정보는 학사 관리 업무에 필수, 정비소 관리에는 필요 없음
- 이처럼 업무와 관련 없는 엔터티는 불필요한 복잡성만 증가

### 2. 고유한 식별자
- 엔터티는 각각 데이터를 유일하게 구분할 수 있는 고유한 식별자를 가져야 함
- 예) 학생(엔터티) → 학번을 통해 각 학생 구분
- 예) 학번(엔터티) → 학생을 구분할 수 있는 식별자

### 3. 2개 이상의 인스턴스 포함
- 엔터티는 정보의 집합, 일반적으로 두 개 이상의 인스턴스를 가짐
- 단 하나의 데이터를 위해 별도의 엔터티를 만드는 것이므로 모델의 효율성을 떨어트림

### 4. 반드시 하나 이상의 속성
- 자신을 설명하는 속성을 가져아 함
- 속성은 엔터티를 설명하는 상세 정보
- 속성이 없는 엔터티는 이름만 존재, 내용이 없음

### 5. 다른 엔터티와 최소 하나 이상의 관계를 맺어야 함
- 엔터티는 다른 엔터티와 관계를 맺음으로써 의미 있는 정보를 만듬
- 예) 주문(엔터티) → 어떤 고객, 어떤 상품을 주문했는지 다른 엔터티와 관계 맺음

## 3. 엔터티의 분류

### 1. 형태

엔터티가 눈에 보이는 실체, 개념적 대상, 업무 과정에서 발생하는 사건인지에 따라 구분하는 방식

| 구분     | 설명                      | 예시                         |
| ------ | ----------------------- | -------------------------- |
| 유형 엔터티 | 물리적 형태가 있는 대상           | 학생, 교수, 강의실                |
| 개념 엔터티 | 물리적 형태는 없지만, 관리해야 하는 대상 | 선형결합의 점들을 시각화              |
| 사건 엔터티 | 업무 수행에 따라 발생하는 행위나 사건   | `np.linalg.matrix_rank(V)` |
### 2. 발생 시점

엔터티가 어떻게 만들어지고 어떤 역할을 하는지에 따라 구분하는 방식

| 구분     | 설명                                                   | 예시           |
| ------ | ---------------------------------------------------- | ------------ |
| 기본 엔터티 | 업무에 원래부터 존재하는 정보, 다른 엔터티의 존재에 의존하지 않고 독립적으로 생성되는 엔터티 | 학생, 교수, 강의실  |
| 중심 엔터티 | 기본 엔터티로부터 파생되어 업무 처리의 중심적인 역할을 수행하는 엔터티              | 학기, 강의       |
| 행위 엔터티 | 두 개 이상의 엔터티 사이에 발생하는 행위에 의해 파생되는 엔터티                 | 수강신청, 성적, 출결 |

# 02. 속성

- 엔터티에 대한 구체적인 정보
- 의미상 더 이상 분리되지 않은 최소의 데이터 단위
- 좋은 속성은 업무와 직접적인 관계, 해당 엔터티를 정의하는 데 필수적인 것들로만 구성
- 예) 학사 관리 업무 → 학생 엔터티 정의할 때 학번과 학과는 필수적, 그 외에는 필수적X

![[02. 엔터티, 속성-1791116154995.webp]]

## 1. 속성값

- 하나의 인스턴스에서 톡정 속성이 가지는 실제 데이터
- 예) 학생(엔터티) → 홍길동이라는 하나의 인스턴스가 있다면 홍길동은 인스턴스가 가지는 각 속성값이다.
- 원칙적으로 **하나의 속성은 하나의 값만 가짐** → 단일값 속성
- 여러 값을 가질 수 있는 다중값 속성도 존재하긴 하나 일반적으로 엔터티로 분리해 설계

## 2. 엔터티, 인스턴스, 속성값

- 엔터티, 인스턴스, 속성값에 대한 관계 규칙을 정의, 모델의 완성도와 효율성 판단 기준
- 1. 한 개의 엔터티는 두 개 이상의 인스턴스를 가진다.
- 2. 한 개의 엔터티는 두 개 이상의 속성을 갖는다.
- 3. 한 개의 속성은 하나의 속성값을 갖는다.


## 3. 속성의 분류

### 1. 특성에 따른 분류
속성 출처와 성격에 따라 분류하는 방식

- 기본 속성: 업무 분석을 통해 자연스럽게 정의되는 속성
- 예) 고객(엔터티) → 고객명, 생년월일
- 설계 속성: 업무는 없지만, 데이터 모델링 과정에서 인위적으로 생성하는 속성
- 예) 동명이인 구분위한 고객번호, 상품코드

### 2. 구성 방식에 따른 분류
속성이 엔터티 내에서 어떤 역할을 하는지에 따라 분류하는 방식

- PK(Primary Key, 기본키): 엔터티 내의 각 인스턴스를 유일하게 식별하는 속성
- 예) 학생의 학번은 각 학생을 유일하게 구분하므로 기본키

- FK(Foreign Key, 외래키): 다른 엔터티의 기본키를 참조해 엔터티 간의 관계를 연결하는 속성
- 예) 학생(엔터티)안의 학과코드, 학과 엔터티는 기본키를 참조해, 학생이 어떤 학과에 소속되어 있는지 관계를 맺어주므로 외래키가 됨

- 일반 속성: PF나 FK가 아닌 나머지 속성
- 예) 학생(엔터티)(학생명), 학과(엔터티)(학과명)처럼 식별자나 관계 연결에 사용되지 않고 대상을 설명함

## 5. 도메인
도메인(Domain)이란 **하나의 속성이 가질 수 있는 값의 범위와 규칙을 정의한 것**

- 데이터 타입: 속성에 문자, 숫자, 날짜 등 어떤 종류의 데이터가 들어올 수 있는지 정함
- 크기: 문자의 최대 길이 또는 숫자의 전체 자릿수 등을 정함
- 허용값(CHECK): '남' OR '여'처럼 정해진 값만 입력 혹은 '가격은 0보다 커야 한다'와 같은 조건부여 
- NULL 허용 여부: 값을 비워둘 수 없는지, 아니면 반드시 입력하는지 정함
- 기본값(Default): 값을 생략했을 때 자동으로 입력될 기본값 정함
