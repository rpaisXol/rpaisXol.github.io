# 1. RDBMS

- 데이터를 표(테이블) 형태로 저장하고, 기본키(PK)와 외래키를 이용해 여러 테이블을 서로 연결하고 관리하는 데이터베이스
- 데이터를 테이블(Row, Column) 형태로 저장
- 기본키(PK)로 각 행을 구분
- 외래키(FK)로 테이블 가 관계를 만듬
- SQL(Structured Query Language)은 RDB의 데이터를 조회, 수정, 삭제하고 관리하기 위한 표준 언어
- RDBMS(Relational Database Management System)는 관계형 데이터베이스(RDB)를 SQL 등을 이용하여 생성, 저장, 조회, 수정, 삭제할 수 있도록 관리하는 소프트웨어
- 대표적으로 MySQL, PostgreSQL, Oracle Database 등이 존재

# 2. 기본키(Primary Key, PK)

- 테이블에서 각 행을 유일하게 구분하는 컬럼
- 같은 값이 존재할 수 없음
- NULL도 허용하지 않음
- 보통 하나의 테이블에 하나만 존재

예) 학생 테이블
- 학생 테이블의 학생번호가 기본키
- 학생번호는 중복되지 않는다.
- 하나의 학생번호로 한명의 학생을 정확히 찾을 수 없다.

# 3. 외래키(Foreign Key, FK)

- 외래키(FK)는 다른 테이블의 기본키를 참조하는 컬럼이다.
- 여기서 성적 테이블의 학생번호(FK)는 학생 테이블의 학생번호(PK)를 참조
- 학생 테이블에 존재하는 학생번호만 성적 테이블에 데이터를 추가할 수 있음

예) 학생 테이블, 성적 테이블

![[1) RDB, 기본키, 외래키, 관계, 인덱스-1793149540497.webp]]

```text
학생 
1001 홍길동 

↓ 

성적 
1001
95
```

# 3. 관계(Relationship)

- 테이블끼리 연결되어 있는 것을 관계(Relationship)
- 관계를 만들기 위해 외래키를 사용하는 것이 일반적
- 외래키(Foreign Key)는 관계를 데이터베이스에서 실제로 강제하는 제약 조건
- 외래키가 없어도 관계가 설정되지만, 잘못된 데이터가 입력을 제한하는 데이터 무결성을 DBMS가 보장하진 않음

예) 학생 한명을 0개 이상 성적이 참조, 학생과 성적이라는 1:N 관계가 만들어짐

```text
**① 1 : 1**

​

사원

↓

사원증

​

한 사원은 한 개의 사원증만 가진다.

​

**② 1 : N (가장 많이 사용)**

​

학생 1명

↓

성적 여러 개

​

학생 한 명은 여러 성적을 가질 수 있다.

​

**③ N : M**

​

학생 ↔ 과목

​

학생 여러 명이 여러 과목을 수강한다.

​

- 이 경우 데이터 중복 및 이상현상 같은 **데이터무결성**의 문제가 발생

- 데이터 중복 및 이상 현상을 막기 위해서 N:M(다대다) 관계를 중간 테이블로 분리

- "학생:과목"의 N:M 관계는 대부분 **두 개의 1:N 관계로 분해**한다.

학생 → 수강 : **1:N**

과목 → 수강 : **1:N**
```

이처럼 **중간 테이블(수강)**을 두면 N:M 관계를 두 개의 1:N 관계로 바꿀 수 있고, 이것이 관계형 데이터베이스에서 가장 안정적이고 정규화된 설계이다.

N:M 관계 같은 잘못된 데이터베이스 설계는 같은 정보를 여러 번 저장하게 만들고, 그 결과 중복과 수정·삽입·삭제 이상이 발생한다. 이를 해결하기 위해 정규화하여 테이블을 분리하고, 기본키(PK)와 외래키(FK)로 관계를 맺는다.

# **5. 인덱스(Index)**

- 인덱스(Index)는 **검색을 빠르게 하기 위한 자료구조**이다.
- 우리가 보는 책 마지막에 있는 색인을 생각하면 쉽게 이해된다.
- 찾고 싶은 단어가 있으면 처음부터 한 장씩 넘기지 않는다. 
- 맨 뒤의 색인을 찾아보고 페이지로 바로 이동하여 찾는다.
- 데이터베이스도 같다. 인덱스가 없으면 다음과 같이 처음부터 모두 검사한다.

```text
1 2 3 4 5 6 ... 1000000
```

**※ 기본키 vs 인덱스**

* 기본키나 외래키는 RDBMS에 따라 자동으로 인덱스키가 되는 경우가 많다.
