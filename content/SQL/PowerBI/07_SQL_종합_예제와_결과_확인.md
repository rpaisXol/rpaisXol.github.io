## 1. 개념의 뜻과 동작 원리

### 1-1. 종합 조회의 단위

- 복잡한 SQL도 먼저 결과 한 행이 고객·주문·부서 중 무엇을 나타내는지 정하면 읽기 쉬움. 계산식보다 행 단위를 먼저 맞추는 것이 핵심.
- 각 단계에서 입력 행 수, 고유 키, NULL 가능성, 집계 기준을 확인하면 중간 결과가 잘못된 지점을 찾기 쉬움.

### 1-2. 단계별 계산의 연결

- 원본을 필요한 단위로 집계하고, 그 결과를 관계에 맞춰 연결한 뒤 최종 표시를 구성. 여러 단계의 목적을 CTE 등으로 나누면 설명에 도움.
- 집계 전 필터와 집계 후 필터, 순위 계산 전후의 필터를 구별. 같은 조건 문자열이라도 놓인 단계가 결과 의미를 바꿀 수 있음.

### 1-3. 결과 확인의 기준

- 전체 합계뿐 아니라 대표 행·비어 있는 그룹·중복 키·NULL 사례를 함께 확인. 숫자 하나가 맞았다는 이유로 모든 조건이 옳다고 단정하지 않음.
- 예제의 초기 상태를 고정하고 한 조건씩 바꿔 확인하면 왜 결과가 달라졌는지 이해하기 쉬움. 이를 긴 코드를 외우는 대신 개념을 연결하는 데 사용.
- 복합 SQL도 입력 행, 조건 적용, 그룹의 단위, 계산값, 출력 순서로 나누면 결과를 추적하기 쉬움. 작성 순서를 실제 물리 실행 순서로 단정하지 말고, 개념적인 처리 단계에 따라 예상 결과를 확인.

## 2. 세부 정의와 관련 규칙

### 2-1. 정의와 기본 규칙


- 보고서는 측정 단위를 먼저 정함.
- 직원 수, 급여 합, 보너스 합을 한 JOIN에서 무작정 계산하면 일대다 중복으로 과대 계산할 수 있음.

- 보너스를 직원별로 먼저 집계하고 부서를 LEFT JOIN으로 보존하면 빈 부서까지 보여줄 수 있음.
- NULL 급여를 0으로 표시하는 것은 업무 해석을 동반함.

- 재고 감소는 충분한 수량 조건을 UPDATE에 함께 쓰고 영향받은 행 수를 확인함.
- 정상값뿐 아니라 미존재 상품·부족 재고·중복 요청도 검사하는 방향으로 확장함.

## 4. 예제

- **상황**: 부서별 데이터는 (10,2), (10,3), (20,4)이며 부서 합계를 구하려는 상황.
- **질문**: 부서 10의 값 2, 3과 부서 20의 값 4를 부서별로 합산하면 몇 행이며 각 합계는 얼마인가?
- **실행 기준**: SQLite 확인용. 입력 데이터와 필요한 객체를 코드 안에 포함.

```sql
WITH t(d,v) AS (VALUES (10,2),(10,3),(20,4))
SELECT d,SUM(v) FROM t GROUP BY d ORDER BY d;
```

- **결과**: 10번 합계 5, 20번 합계 4.
- **풀이 ①**: GROUP BY d가 결과 한 행을 부서 하나로 정하므로 두 그룹을 만듦.
- **풀이 ②**: 부서를 한 행의 단위로 정한 뒤 값을 합산. 10번은 2+3=5, 20번은 4이므로 출력은 두 행.
