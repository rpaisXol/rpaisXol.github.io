## 1. 개념의 뜻과 동작 원리

### 1-1. 스키마와 현재 데이터

- 스키마는 저장할 정보의 구조와 규칙이고 인스턴스는 특정 시점에 실제 저장된 데이터 상태. 학생 표의 열 정의와 오늘의 학생 명단을 구별.
- 스키마가 같아도 데이터는 계속 바뀔 수 있음. 반대로 구조를 바꾸는 일은 현재 값의 단순 수정과 다른 영향을 가질 수 있음.

### 1-2. 세 가지 관점

- 외부 스키마는 사용자별로 필요한 관점, 개념 스키마는 전체 논리 구조, 내부 스키마는 실제 저장 방식의 관점으로 이해.
- 각 단계는 서로 연결되지만 모든 사용자가 저장 파일이나 인덱스 구조까지 직접 알아야 하는 것은 아님. 관점의 분리가 변경 영향을 줄이는 데 도움.

### 1-3. 데이터 독립성

- 논리적 독립성은 개념 구조 변경이 외부 관점에 미치는 영향을 줄이는 성질, 물리적 독립성은 저장 방식 변경이 논리 구조에 미치는 영향을 줄이는 성질.
- 독립성은 아무 변경이나 영향 없이 할 수 있다는 절대 보장이 아님. 어떤 계층의 변경을 다른 계층에서 덜 의식하도록 만드는지로 이해.
- 스키마는 데이터의 구조와 규칙이고 인스턴스는 특정 시점에 저장된 실제 내용. 외부·개념·내부 수준을 구분하면 사용자가 보는 모습과 전체 논리 구조, 물리 저장 방식을 각각 이해할 수 있음.

## 2. 세부 정의와 관련 규칙

### 2-1. 정의와 기본 규칙


- 스키마는 구조·자료형·제약의 정의이고 인스턴스는 특정 시점 데이터 상태임.
- 구조가 같아도 행은 계속 바뀜.

- 외부 스키마는 사용자별 관점, 개념 스키마는 전체 논리 구조, 내부 스키마는 저장 구조임.

- 논리적 독립성은 개념 변화의 외부 영향 완화, 물리적 독립성은 내부 저장 변화의 개념 영향 완화임.
- 인덱스 변경은 대표적인 물리 설계 변화임.

## 4. 예제

- **상황**: 학생(학번,이름) 구조에 오늘 학생 30명이 저장됨.
- **질문**: 학생(학번, 이름) 구조와 오늘 저장된 학생 30명은 각각 무엇인가? 학생 한 명을 추가하면 어느 쪽이 바뀌는가?
- **정답**: 구조는 스키마, 오늘의 실제 30명 데이터는 인스턴스.
- **풀이 ①**: 열 구성이라는 설계와 그 구조에 들어 있는 현재 행을 분리.
- **풀이 ②**: 설계 규칙과 현재 상태의 차이. 학생을 추가하면 인스턴스가 바뀌고 열 구조인 스키마는 그대로 유지.
