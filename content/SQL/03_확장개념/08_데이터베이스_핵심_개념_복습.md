## 1. 개념의 뜻과 동작 원리

### 1-1. 복습에서 먼저 확인할 질문

- SQL 문제를 읽을 때 행의 단위, 중복 허용, NULL 가능성, 조건의 위치를 먼저 확인. 서로 다른 문법도 이 네 관점으로 연결하면 공통 원리를 찾기 쉬움.
- 정답 숫자를 외우기보다 어떤 행이 계산에 들어갔는지 설명. 입력이 조금 바뀌어도 같은 규칙을 적용할 수 있어야 개념을 이해한 것.

### 1-2. 설계와 조회의 연결

- 키·관계·필수값 같은 모델의 규칙은 조인 개수와 NULL 가능성에 직접 영향. 모델링과 SQL을 별도 암기 목록으로만 보지 않음.
- 함수·집계·윈도우·트랜잭션은 계산 대상과 범위가 다름. 무엇을 한 번에 묶는지 구분하면 비슷한 용어의 차이가 명확해짐.

### 1-3. 오답을 줄이는 복습

- 틀린 이유를 조건 누락·분모 혼동·동점 처리·제품 차이처럼 개념으로 분류. 같은 개념을 다른 짧은 예제에 다시 적용하면 복습의 효율이 높음.
- 공통 원리와 DBMS 전용 규칙을 분리해 정리. 제품을 바꿨는데도 같은 결과를 당연하게 기대하는 습관을 줄이는 것이 중요.
- 복습에서는 용어의 정의뿐 아니라 행과 값, 구조와 내용, 조회와 변경을 구별하는 기준을 함께 떠올리는 것이 효과적. 특히 NULL·중복·조인 행 수처럼 여러 단원에 걸치는 규칙을 연결하면 결과 예측의 오류를 줄일 수 있음.

## 2. 세부 정의와 관련 규칙

### 2-1. 정의와 기본 규칙


- 공통 우선 주제는 키·정규화·무결성, SQL 분류, NULL과 집계, 조인, 서브쿼리, 그룹 필터, 트랜잭션임.
- SQLD는 모델링·식별자·관계와 윈도우·집합·계층형·그룹 소계의 차이를 반복 설명해 확인.

- 정보처리기사는 데이터베이스 기초, 관계대수, 함수 종속·정규화, SQL 작성, 트랜잭션·회복·동시성 개념을 함께 복습함.
- 이 자료는 전체 정보처리기사 실기 영역을 다루지는 않음.

- 결과 예측은 FROM/JOIN 후 행 수 → WHERE → GROUP BY → HAVING → SELECT → 정렬 순서로 추적함.
- DBMS 전용 문법과 NULL 처리를 먼저 확인하고 빈칸은 주변 문장과 목표 결과에서 근거를 찾음.

## 4. 예제

- **상황**: 숫자 0인 행과 NULL인 행이 하나씩 저장되어 있는 상황.
- **질문**: 0과 NULL이 한 행씩 있을 때 COUNT(*)와 COUNT(v)는 각각 얼마인가? 0이 제외되는지도 확인하라.
- **실행 기준**: SQLite 확인용. 입력 데이터와 필요한 객체를 코드 안에 포함.

```sql
WITH t(v) AS (VALUES (0),(NULL))
SELECT COUNT(*),COUNT(v) FROM t;
```

- **결과**: 행 수 2, 값 수 1.
- **풀이 ①**: 0은 저장된 실제 값이고 NULL은 결측이므로 두 상태를 같은 것으로 취급하지 않음.
- **풀이 ②**: 0은 실제 값이고 NULL은 결측이라는 차이를 복습. 0도 COUNT(v)에 포함되므로 결과는 2와 1.
