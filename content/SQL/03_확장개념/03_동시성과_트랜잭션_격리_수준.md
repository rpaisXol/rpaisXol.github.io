## 1. 개념의 뜻과 동작 원리

### 1-1. 동시 실행의 문제

- 여러 트랜잭션이 같은 데이터를 읽고 바꾸면 단독 실행과 다른 관찰이 생길 수 있음. 격리는 이런 간섭을 어느 수준까지 제어할지와 연결.
- 아직 확정하지 않은 값을 읽는 더티 리드, 같은 행을 다시 읽었을 때 값이 달라지는 반복 불가능 읽기, 같은 조건의 행 구성이 달라지는 팬텀을 구별.

### 1-2. 격리 수준의 해석

- 표준 격리 수준 이름은 허용할 수 있는 현상을 설명하는 출발점. 실제로 무엇이 차단되는지는 DBMS의 잠금·스냅샷 등 구현에 따라 더 강하거나 세부 차이가 있을 수 있음.
- 격리를 높이면 모든 업무가 무조건 빨라지는 것은 아님. 대기·충돌·재시도 등 비용과 일관성 요구를 함께 고려.

### 1-3. 학습할 때의 판단 기준

- 한 세션의 COMMIT·ROLLBACK만 읽는 문제와 서로 다른 세션이 무엇을 볼 수 있는지 묻는 문제를 구분. 시간순으로 각 세션의 동작을 적으면 이해가 쉬움.
- 일반 원리와 특정 제품의 실제 보장 수준을 분리하고, 다른 제품에서 본 결과를 동일한 이름에 무조건 적용하지 않음.
- 동시성 제어는 여러 트랜잭션이 같은 데이터를 사용할 때 결과의 일관성을 지키는 장치. 격리 수준은 관찰 가능한 현상과 연결되며, 표준 수준의 개념과 각 DBMS의 잠금·버전 처리 방식은 구분해야 함.

## 2. 세부 정의와 관련 규칙

### 2-1. 정의와 기본 규칙


- 더티 리드는 미커밋 값 읽기, 비반복 읽기는 같은 행 값 변화, 팬텀은 같은 조건의 행 집합 변화임.
- 분실 갱신도 대표적인 동시 변경 위험임.

- 표준 수준은 READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE 순으로 이해함.
- 수준의 최소 보장과 제품의 MVCC 구현을 구분함.

- 잠금은 충돌 접근을 제어하고 MVCC는 여러 버전을 이용함.
- 교착상태는 서로 자원을 기다려 진행하지 못하는 경우임.
- 아래 단일 연결 예제는 동시성을 증명하는 예제이 아니라 변경 단위의 원리 실습임.

## 4. 예제

- **상황**: 한 트랜잭션이 같은 행을 두 번 읽는 사이 다른 작업이 값을 확정.
- **질문**: 같은 행을 두 번 읽는 사이 다른 트랜잭션이 값을 바꾸고 확정하면 어떤 읽기 현상이 생길 수 있는가?
- **정답**: 격리 조건에 따라 다시 읽은 값이 달라질 수 있음.
- **풀이 ①**: 첫 조회와 두 번째 조회 사이에 다른 작업의 확정이 끼어드는 상황을 확인.
- **풀이 ②**: 반복 불가능 읽기의 개념이며 실제 허용 여부는 제품과 격리 수준으로 판단. 이를 반복 불가능 읽기라고 하며, 실제 발생 가능성은 적용한 격리 수준과 DBMS 구현을 확인.

## 5. 복습 요약

- **관측 대상**: 동시 실행에서 어떤 이상 현상이 가능한가?. 내용과 적용 조건을 함께 확인.
- **확인 기준**: 격리 수준 이름과 제품별 구현을 구분.. 내용과 적용 조건을 함께 확인.
- **다시 확인**: 제품·버전·데이터 조건 변경 시 재검증. 내용과 적용 조건을 함께 확인.
