## 1. 개념의 뜻과 동작 원리

### 1-1. 관계대수와 SQL의 연결

- 관계대수는 관계를 입력받아 관계를 만드는 연산으로 조회를 설명하는 틀. 선택은 행 조건, 투영은 필요한 속성, 조인은 관계 연결과 대응하여 생각.
- SQL은 이런 목적을 표현하지만 모든 결과 규칙이 관계대수의 집합 의미와 동일하지는 않음. 특히 중복과 NULL의 처리를 주의.

### 1-2. 주요 연산의 목적

- 선택과 투영은 각각 행과 열을 다루는 관점이므로 서로 바꾸어 외우지 않음. 카티션곱은 가능한 조합을, 조인은 조건에 맞는 연결을 나타냄.
- 디비전은 모든 요구 대상을 만족하는 항목을 찾는 질문과 연결. 실제 SQL에서는 NOT EXISTS 등의 조합으로 표현할 수 있으며 문법 대응이 한 가지로 고정된 것은 아님.

### 1-3. 집합과 중복의 차이

- 관계대수의 일반적인 집합 관점은 중복을 제거하지만 SQL SELECT는 기본적으로 중복을 허용할 수 있음. DISTINCT가 필요한지 목적에 따라 판단.
- 표시 순서 역시 관계의 본질적 성질로 보지 않음. SQL 결과의 행 순서가 필요하면 별도 정렬을 지정해야 함.
- 관계대수는 관계에 대한 연산을 통해 원하는 결과를 표현하는 이론적 도구. SQL은 중복 행과 NULL을 다루므로 집합 이론의 결과를 그대로 대입하기 전에 중복 제거 여부와 결측 규칙을 확인.

## 2. 세부 정의와 관련 규칙

### 2-1. 정의와 기본 규칙


- 선택은 조건에 맞는 행, 투영은 열, 조인은 관련 튜플의 결합임.
- 디비전은 모든 필수 대상과 관계를 맺은 값을 찾는 연산임.

- 순수 관계대수는 집합 기반이므로 투영 등에서 중복이 없음.
- SQL은 기본적으로 중복 행을 허용해 DISTINCT를 별도로 사용할 수 있음.

- 두 관계의 합집합·교집합·차집합은 대응 속성의 구조와 도메인이 맞는 합병 가능 조건을 생각함.
- SQL의 집합 연산도 열 개수와 타입 호환성을 확인함.

## 4. 예제

- **상황**: 값 1, 1, 2가 저장되어 있고 SQL에서 중복 제거 결과를 확인하는 상황.
- **질문**: SQL 입력값 1, 1, 2에 DISTINCT를 적용하면 무엇이 남는가? 결과의 중복 여부를 설명하라.
- **실행 기준**: SQLite 확인용. 입력 데이터와 필요한 객체를 코드 안에 포함.

```sql
WITH t(v) AS (VALUES (1),(1),(2))
SELECT DISTINCT v FROM t ORDER BY v;
```

- **결과**: 1, 2.
- **풀이 ①**: 원본에는 1이 두 번 있지만 DISTINCT는 동일한 출력값을 한 번만 남김.
- **풀이 ②**: SQL의 기본 중복 허용과 중복 제거 결과를 구분. 같은 값 1은 한 번만 나오므로 결과는 중복 없는 두 행.
