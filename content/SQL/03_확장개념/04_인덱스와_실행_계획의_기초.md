## 1. 개념의 뜻과 동작 원리

### 1-1. 인덱스의 목적

- 인덱스는 필요한 행을 찾는 데 쓰는 별도 접근 구조. 책의 찾아보기처럼 전체를 모두 읽는 대신 후보를 좁힐 수 있게 하는 것이 기본 아이디어.
- 원본 데이터와 별개로 유지할 구조가 생기므로 공간과 변경 비용이 필요. 조회를 빠르게 할 가능성과 입력·수정의 추가 비용을 함께 고려.

### 1-2. 실행 계획과의 관계

- 인덱스가 존재해도 DBMS가 항상 사용하는 것은 아님. 선택할 행의 비율·자료량·통계·비용 추정에 따라 전체 읽기를 고를 수 있음.
- 실행 계획은 SQL의 논리 의미가 아니라 엔진이 처리하기 위해 고른 접근 방법을 보여 주는 관점. 조건과 자료가 바뀌면 계획도 달라질 수 있음.

### 1-3. 주의해서 볼 항목

- 복합 인덱스는 열 순서와 조건 형태가 활용에 영향을 줄 수 있음. 인덱스를 만들었다는 사실만으로 모든 검색이 같은 이익을 얻는 것은 아님.
- 인덱스의 정렬 구조와 최종 결과 정렬 보장은 구분. ORDER BY 없는 결과 순서를 인덱스 존재만으로 가정하지 않음.
- 인덱스는 특정 조건의 행을 찾는 경로이고 실행 계획은 DBMS가 선택한 접근·조인 방식의 설명. 읽을 행의 비율과 통계에 따라 비용이 달라지므로 인덱스의 존재만으로 빠른 실행을 보장하지는 않음.

## 2. 세부 정의와 관련 규칙

### 2-1. 정의와 기본 규칙


- 인덱스는 검색과 정렬에 도움이 될 수 있지만 공간과 쓰기 유지 비용이 듬.
- 모든 조회를 항상 빠르게 하는 것은 아님.

- B트리 계열은 일반적인 범위 검색에 적합함.
- 복합 인덱스의 열 순서, 선두 열 조건, 선택도와 통계가 계획에 영향을 줌.
- 함수 적용도 함수 기반 인덱스 지원 여부를 확인함.

- EXPLAIN QUERY PLAN 등으로 계획을 확인하되 문구는 버전과 통계에 따라 달라짐.
- 고급 튜닝은 SQLD 기본 학습 후의 실무 확장으로 구분함.

## 4. 예제

- **상황**: 고객번호 한 건 검색과 전체 매출 합계 조회를 비교.
- **질문**: 고객번호 한 건 검색과 전체 매출 합계에서 같은 인덱스가 항상 같은 효과를 내는가? 이유를 설명하라.
- **정답**: 같은 인덱스가 두 조회에 동일하게 유리하다고 단정할 수 없음.
- **풀이 ①**: 첫 조회는 일부 행을 찾지만 둘째 조회는 많은 값을 읽어 합산해야 함.
- **풀이 ②**: 읽을 자료의 범위와 비용이 다르기 때문. 읽을 범위가 다르므로 인덱스가 두 조회에 항상 같은 효과를 내는 것은 아님.

## 5. 복습 요약

- **관측 대상**: 인덱스가 있어도 실행 계획이 달라지는 이유는?. 내용과 적용 조건을 함께 확인.
- **확인 기준**: 조건·자료량·통계에 따른 읽기 방식을 관찰.. 내용과 적용 조건을 함께 확인.
- **다시 확인**: 제품·버전·데이터 조건 변경 시 재검증. 내용과 적용 조건을 함께 확인.
